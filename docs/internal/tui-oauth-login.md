# TUI /login and /logout

gi's `/login` and `/logout` follow Pi's interactive flows
(`interactive-mode.js`: `handleLoginCommand` and `showOAuthSelector`). The
code is in `internal/tui/login.go` and `internal/inference/login.go`.

## /login

- A bare `/login` opens Pi's authentication-method menu, which offers "Sign in
  with an account" and "Sign in with an API key". Choosing a method opens Pi's
  provider selector (`OAuthSelectorComponent`) for that method.
- `/login <provider>` matches the provider by ID or name.
  - When the provider has one sign-in method, that method starts.
  - When it has both, the method menu opens for that provider.
  - Otherwise the provider selector opens, with the argument as the search.
- The provider selector shows each provider's method
  (`[subscription]`, `[account]`, `[API key]`) and its status:
  - `✓ configured`
  - `• not configured`
  - `• <method> configured`, when the provider is set up with the other method
  - `✓ environment`, when an environment variable provides the key
- The login runs in Pi's login dialog (`LoginDialogComponent`):
  - **Account:** the dialog runs go-ai's OAuth flow for the provider. It shows
    the sign-in URL with click and copy hints (Pi 1.0.1's `AuthUrlComponent`,
    `internal/tui/auth_url.go`) and opens the browser. Ctrl+X copies the URL
    (native clipboard, else OSC 52 over SSH or without a display) and the
    hint shows the result. The flow's
    prompts take the pasted code or redirect URL, its menus appear over the
    dialog, and its progress messages are listed.
  - **API key:** the dialog asks for the key.
- Credentials are saved to `auth.json` in Pi's format:
  - an account: `{"type":"oauth","refresh","access","expires",...}`
  - an API key: `{"type":"api_key","key":...}`
- After saving, the transcript shows Pi's status, for example
  "Logged in to X. Credentials saved to <path>".
- Escape or Ctrl+C cancels the login and reopens the menu or selector it
  started from, as Pi's `onBack` does.

The providers and their methods are Pi's built-in list, generated by
`scripts/golden-login-providers.mjs` into
`internal/inference/login_providers_gen.go`. The account option is offered
only for providers whose OAuth flow go-ai implements.

### Argument completion

`/login ` completes provider IDs as Pi's `getArgumentCompletions` does:

- There is one item per provider.
- The description gives the provider's name and its methods, for example
  "Anthropic · subscription/API key".
- Items are fuzzy-matched on the ID, the name and the methods.

`/model ` and `/thinking ` complete in the same way as in Pi:

- `/model ` offers the scoped models (or, without a scope, every available
  model) as `provider/id`.
- `/thinking ` offers the levels the model supports.

The code is in `internal/tui/slash_menu.go`.

## /logout

- A bare `/logout` lists the credentials stored in `auth.json` in Pi's
  selector.
  - Choosing an account entry removes it and shows Pi's "Logged out of X".
  - Choosing an API key entry removes it and shows Pi's "Removed stored API
    key for X. …".
- With nothing stored, `/logout` shows Pi's message: "No stored credentials to
  remove. …".
- `/logout <provider>` removes that provider's entry directly. This is a gi
  addition, kept for scripts.

## API key format

Pi stores API keys as `{"type":"api_key","key":...}`. gi reads both `key` and
its earlier `apiKey` field. gi's web settings now write `key`.

## Differences from Pi

- go-ai's sign-in flows take no cancellation signal. Cancelling closes the
  dialog, and the flow's result is ignored when it ends.
- Flows that race the browser callback against a pasted code (ChatGPT, go-ai
  v1.0.1's `OnPromptContext`) end the prompt when the callback wins: the input
  stops taking an answer.
- The environment status shows `✓ environment` instead of the variable's
  name.
- gi does not select the provider's default model after a login.
- gi does not refresh the model catalogue after a login.
- gi does not offer Radius's MCP setup.
- Stored keys are used literally. Pi's command (`!…`) and template values are
  not resolved.
- The provider search text leaves out Pi's method name.
- go-ai reports device-code flows (GitHub Copilot, Kimi) through its auth URL
  callback with "Enter code: …" instructions, so they show the copy hint that
  Pi's device-code screen (`showDeviceCode`) leaves out. The port of that
  screen is ready for go-ai's device-code events.

Golden tests: `scripts/golden-login.mjs` → `TestLoginUIMatchesPi`. The flows
are covered by `TestLoginAPIKeyAndLogoutFlow` and `TestLoginOAuthFlow`.
