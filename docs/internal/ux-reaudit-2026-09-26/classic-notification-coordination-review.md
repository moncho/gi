# Classic local notification coordination, 29 September 2026

The installed Piclaw 3.2.4 Classic UI published one selected-chat browser presence record and withdrew it on `pagehide` in each of six Chromium/WebKit phone, tablet and desktop fixture cases. `make test-piclaw-notification-presence` observed one synthetic `/agent/push/presence` POST per case, a `piclaw.notifications.presence.*` local-storage record scoped to `web:default`, and removal of that record after a `pagehide` event. This covers the mount and withdrawal path without asking for notification permission or delivering a system notification.

The shipped `app.bundle.js.map` contains the mounted `useNotifications` hook and `notification-delivery-coordinator.ts`. The coordinator filters live same-device presence by selected chat, suppresses when any candidate is visible, and otherwise elects the lexicographically first client ID. Gi's `web/src/gi-notifications-state.ts` calls that same coordinator through its own lock and seen-list. `make test-notification-helpers` checks candidate and cross-client decisions; `make test-ux-notifications` uses mocked permission and delivery across six browser projects, including visible-tab suppression, hidden ownership and logout. The Gi tests are not tagged to `@ux-extra-011`.

The installed browser probe did not demonstrate two active clients receiving the same event or actual notification delivery. The client selection helper and Gi fixture tests supply bounded evidence for those subclauses. Server presence fanout, OS permissions/sound, cross-device coordination, physical devices and a full mounted Piclaw delivery journey have not been tested. Leave `@ux-extra-011` without whole-clause parity acceptance; do not port the helper again solely because the source matches.
