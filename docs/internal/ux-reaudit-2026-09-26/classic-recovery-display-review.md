# Classic recovery display, 28 September 2026

The installed Piclaw 3.2.4 Classic client and Gi do not display the same eight recovery fixture rows. `make test-piclaw-recovery-display` used the shipped UI with 23 control-intent and 21 placeholder posts from Gi's fixture files in each of six Chromium/WebKit phone, tablet and desktop cases. It observed the same eight differences in every case; the other 36 rows matched the fixture visibility expectations. This compares displayed posts only. It did not run recovery, persist a backend message, exercise search or test a physical device.

| Clause | Installed observation | Boundary |
| --- | --- | --- |
| `@ux-extra-012` | Three valid protected controls were hidden, as were `legacy-partial-failure` and `legacy-bad-failure`, which Gi keeps visible. | Installed `components/post.ts` accepts a block without typed handoff keys before validating partial primary-failure fields. Gi's `gi-recovery-control.ts` validates those fields even on legacy-shaped blocks. The frozen rule says invalid typed fields do not qualify; whether these mixed legacy/primary-failure blocks fall under that rule needs a contract decision. Leave the mapping qualified, not accepted. |
| `@ux-extra-013` | The empty informational placeholder was hidden. The installed UI also hid the fixture's `file`, `file-ref`, `message-ref`, `attachment-ref`, `resource` and `text-annotation` posts, which Gi displays. | The disposable Classic post for `file` lacked its Gi-native `media_ids` projection. The other five reused Gi content or metadata shapes that do not guarantee renderable Classic text or visible extras after Classic parsing. Installed `post.ts` checks `shouldRenderContent`, `media_ids`, direct cards and submissions. These are fixture-shape observations, not proof that the installed client hides equivalent real attachments or references. |

`make test-ux-recovery-controls` and `make test-ux-recovery-placeholders` retain separate native Gi HTTP/SQLite, reload, search and draft checks. A next oracle fixture should use the installed client's actual message/media representation for the six visible-extra cases. It should independently test the two mixed legacy control blocks against the frozen wording before changing either validator or mapping. No production code, frozen Gherkin or live chat was changed.
